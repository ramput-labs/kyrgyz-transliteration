Транслитерация кыргызского языка на Python: кириллица ⇄ **английская латиница**.
Только буквы `a-z` — ни турецкого алфавита (`ı ş ç ğ ñ`), ни научного
(`ž ô ù ņ â`). Восстановление регистра, восстановление `ө`, `ү` и `ң` по
словарю, чистка «грязного» ввода (двойники букв, ударения, латиница внутри
кириллических слов), схема паспортов ICAO, слаги для URL и консольная утилита,
которая работает и на Windows. Без зависимостей, Python 3.9+.

```python
from kyrgyz_transliteration import to_latin, to_cyrillic, slugify

to_latin("дөңгөлөк")                 # 'dongolok'
to_cyrillic("dongolok")              # 'дөңгөлөк'
to_latin("Кыргыз Республикасы")      # 'Kyrgyz Respublikasy'
to_cyrillic("Kyrgyz Respublikasy")   # 'Кыргыз Республикасы'
to_latin("Айгүл Жумагулова", "passport")   # 'Aigul Zhumagulova' — как в паспорте
to_latin("дѳңгѳлѳк Тaлаc")           # 'dongolok Talas' — ѳ и латинские a/c исправлены
slugify("Ысык-Көл облусу")           # 'ysyk-kol-oblusu'
```

## Главная сложность: ө, ү и ң

В английском алфавите этих букв нет. Кыргызы пишут их латиницей так же, как
`о`, `у` и `н`:

| Кириллица | по-английски |
|---|---|
| дөңгөлөк | `dongolok` |
| донголок | `dongolok` |
| өмүр | `omur` |
| түшүнүк | `tushunuk` |

В одну сторону всё однозначно, обратно — нет: и «дөңгөлөк», и «донголок»
подчиняются гармонии гласных, правилами их не различить. Поэтому обратное
направление идёт через **список кыргызских слов, и он включён по умолчанию**:

```python
to_cyrillic("dongolok")                  # 'дөңгөлөк'  — по словарю
to_cyrillic("dongolok", wordlist=False)  # 'донголок'  — только правилами
```

Слово целиком в словаре искать необязательно: окончание отделяется, к нему
применяется гармония гласных, а конечный согласный основы озвончается
(`к → г`, `п → б`), как этого требует кыргызская морфология:

```python
to_cyrillic("dongolokton")   # 'дөңгөлөктөн'
to_cyrillic("dongologu")     # 'дөңгөлөгү'   (к -> г перед гласной)
to_cyrillic("kitebi")        # 'китеби'      (п -> б перед гласной)
to_cyrillic("okmottun")      # 'өкмөттүн'
to_cyrillic("Omurbekov")     # 'Өмүрбеков'   (русское -ов гармонии не подчиняется)
```

Составные слова ищутся целиком — по частям «Ысык-Көл» от «ысык кол» не отличить:

```python
to_cyrillic("Ysyk-Kol")      # 'Ысык-Көл'
to_cyrillic("Ysyk-Koldon")   # 'Ысык-Көлдөн'
to_cyrillic("uy-bulo")       # 'үй-бүлө'
```

Ни один официальный стандарт не пишет `ң` как `n`: BGN/PCGN, ALA-LC и ODNI
дают `ng`, ISO 9 — `ņ`. Схема `english` следует бытовой записи (`kenesh.kg`,
`Chyngyz`), а если нужна стандартная форма — берите [`bgn_ascii`](#схемы)
(`ң → ng`) или [`passport`](#схемы) (таблица ICAO).

## Схемы

| Схема | Назначение | Чем отличается |
|---|---|---|
| `english` (по умолчанию) | английская латиница: так кыргызы пишут в URL, логинах, мессенджерах | `ж → j`, `й/ы → y` (рядом друг с другом `й → i`: кыйын → `kyiyn`), `х → kh`, `ң → n`, `ө → o`, `ү → u` |
| `english_ascii` | то же, но `ж → zh` | как в русской практике и паспортах |
| `passport` | как в паспорте и ID-карте: таблица кириллицы ICAO Doc 9303 | `ж → zh`, `й → i`, `ю → iu`, `я → ia`, `ё → e`, `ъ → ie`; `ө/ү/ң` в таблице ICAO нет — пишутся `o/u/n` |
| `bgn_ascii` | BGN/PCGN 1979 (национальная система КР для географических названий, en.wikipedia) буквами `a-z` | `ң → ng`, `ö/ü → o/u`, апострофы `ъ/ь` опущены; обратно понимает и `Chüy`, `Özgön`, `n·g` |
| `bgn` | устаревший алиас `english` | оставлен для совместимости; это **не** BGN/PCGN |

Все схемы необратимы без словаря: `ө/о`, `ү/у`, `ң/н` (кроме `bgn_ascii`),
`е/э` и `й/ы` (или `й/и` в `passport`) совпадают в латинице и восстанавливаются
по [словарю](#словарь) и контекстным правилам.

```python
from kyrgyz_transliteration import list_schemes

for scheme in list_schemes():
    print(scheme.name, "-", scheme.title)
```

### Какую схему выбрать

- **`english`** — почти всегда. Так кыргызы пишут латиницей в жизни: в URL,
  логинах, именах файлов, SMS и мессенджерах. Результат читается по-английски,
  состоит только из `a-z`, а `ө`, `ү` и `ң` возвращаются из словаря.
- **`passport`** — когда нужно написать имя так, как оно напечатано в паспорте
  или ID-карте (ГРС использует таблицу ICAO Doc 9303): `Чүй Айтматов →
  Chui Aitmatov`, `Юлия → Iuliia`. Форма для машиночитаемой зоны —
  `to_latin(text, "passport").upper()`.
- **`bgn_ascii`** — для географических названий в стандартной записи
  (`Жеңиш Чокусу → Jengish Chokusu`, `Чоң-Кемин → Chong-Kemin`).
- **`english_ascii`** — если нужно `zh` вместо `j`, но в остальном бытовая
  запись.

Один и тот же текст в разных схемах:

| Кириллица | english | english_ascii | bgn_ascii | passport |
|---|---|---|---|---|
| Ысык-Көл | `Ysyk-Kol` | `Ysyk-Kol` | `Ysyk-Kol` | `Ysyk-Kol` |
| жаңылык | `janylyk` | `zhanylyk` | `jangylyk` | `zhanylyk` |
| Чүй Айтматов | `Chuy Aytmatov` | `Chuy Aytmatov` | `Chuy Aytmatov` | `Chui Aitmatov` |
| кыйын | `kyiyn` | `kyiyn` | `kyiyn` | `kyiyn` |
| Юлия | `Yuliya` | `Yuliya` | `Yuliya` | `Iuliia` |
| Өкмөт | `Okmot` | `Okmot` | `Okmot` | `Okmot` |

Настоящую BGN/PCGN с `ö`, `ü` и апострофами, ISO 9 и ALA-LC с лигатурами
библиотека намеренно не включает: они не укладываются в `a-z`. Официальной
таблицы кыргызской латиницы (проекты 2023–2025 годов) пока нет.

## Нормализация ввода

Реальный кыргызский текст редко бывает «чистым». Перед транслитерацией
`to_latin`, `slugify`, `transliterate` и `detect_script` приводят кириллицу к
норме — иначе в результате вместо `a-z` оставались бы `ѳ`, `ö` или знак
ударения:

| Что встречается | Пример | Результат |
|---|---|---|
| ө/ү/ң набраны буквами других алфавитов | `дѳңгѳлѳк`, `дɵңгɵлɵк`, `дöңгöлöк`, `таҥ`, `таŋ` | `dongolok`, `tan` |
| латинские буквы-двойники внутри кириллического слова (OCR, смешанная раскладка) | `Тaлаc`, `HАРЫН`, `Чyй` | `Talas`, `NARYN`, `Chuy` |
| декомпозированный Unicode (NFD), ударения, титло | `й` как `и` + бреве, `Кыргы́з` | `Kyrgyz` |
| невидимые символы внутри слова | мягкий перенос, нулевой пробел | `Respublika` |
| буквы казахского, узбекского, таджикского, украинского, сербского алфавитов | `Әлия Қазақстан Ұлан`, `Ҷӯра`, `Київ`, `Љубљана` | `Aliya Kazakstan Ulan`, `Jura`, `Kiiv`, `Lublana` |
| римские цифры кириллическими Х/І | `ХХ кылым`, `ХІХ` | `XX kylym`, `XIX` |
| градусы с кириллической С | `25°С` | `25°C` |
| апостроф вместо ъ/ь | `об'ект` | `obekt` |

Правила осторожные: чисто латинские слова (`Facebook'тан`, `iPhoneго`, `HPге`,
`Türkiye`), цифры, пунктуация, эмодзи и другие алфавиты не меняются, а
латинские двойники заменяются только когда все латинские буквы слова —
двойники и кириллица в слове преобладает. Для чистого текста проверка стоит
около 3 % времени. Отключается параметром `normalize=False` (в CLI —
`--no-normalize`); сама функция доступна как `normalize_cyrillic(text)`.

## API

### `to_latin(text, scheme="english", *, normalize=True)`

Кириллица → латиница. Регистр сохраняется, включая многобуквенные замены,
аббревиатуры и аббревиатуры с окончаниями: `Ёлка → Yolka`, `ЁЛКА → YOLKA`,
`ЖЧКнын → JCHKnyn`, `Ч. АЙТМАТОВ → CH. AYTMATOV`. Всё, что не буква (цифры,
пунктуация, разметка, переводы строк), проходит насквозь.

```python
to_latin("Ош шаары")               # 'Osh shaary'
to_latin("КЫРГЫЗ ЭЛИ")             # 'KYRGYZ ELI'
to_latin("Бишкек, 2026-жыл")       # 'Bishkek, 2026-jyl'
to_latin("кыйын айыл")             # 'kyiyn aiyl'
to_latin("подъезд Васильевич")     # 'podyezd Vasilyevich'
to_latin("Жаңыл", "passport")      # 'Zhanyl'
```

### `to_cyrillic(text, scheme="english", wordlist=None)`

Латиница → кириллица. Диграфы имеют приоритет над отдельными буквами
(`shch → щ`, `yo → ё`), а неоднозначные буквы разбираются по контексту:

```python
to_cyrillic("Ysyk-Kol")            # 'Ысык-Көл'  (y после согласной — ы)
to_cyrillic("oy-toy")              # 'ой-той'    (y между гласной и согласной — й)
to_cyrillic("biyik")               # 'бийик'     (y перед узкой гласной — й)
to_cyrillic("aiyl kyiyn")          # 'айыл кыйын' (i рядом с y — й; ayyl/kyyyn тоже понимаются)
to_cyrillic("Said")                # 'Саид'      (гласная + i без y — и)
to_cyrillic("aytsa")               # 'айтса'     (ts на стыке с суффиксом — т + с)
to_cyrillic("Konstitutsiya")       # 'Конституция' (-ция и другие заимствования — ц)
to_cyrillic("rayon")               # 'район'     (yo после a/e/i/u — й + о, после o — ё: боёк)
to_cyrillic("jeek")                # 'жээк'      (ee — долгое ээ, кроме -еев)
to_cyrillic("emgek")               # 'эмгек'     (e в начале слова — э)
to_cyrillic("Vasilyevich")         # 'Васильевич' (ye после согласной — ь + е)
to_cyrillic("Chüy Özgön")          # 'Чүй Өзгөн' (диакритика BGN/PCGN понимается)
```

Адреса сайтов, электронной почты, хэштеги и `@упоминания` не трогаются:
`to_cyrillic("Toluk maalymat: https://www.gov.kg/ky")` → `'Толук маалымат: https://www.gov.kg/ky'`.

Параметр `wordlist` решает, чем восстанавливать `ө`, `ү` и `ң`:

| Значение | Что делает |
|---|---|
| `None` (по умолчанию) или `True` | встроенный список частотных кыргызских слов |
| `False` | ничего, только правила схемы |
| свой `Wordlist` | ваш список слов — см. [Словарь](#словарь) |

### `transliterate(text, scheme="english", direction="auto", wordlist=None, *, normalize=True)`

Направление `"latin"`, `"cyrillic"` или `"auto"`. В режиме `auto` текст, в
котором есть хоть одно кириллическое слово, переводится в латиницу — латинские
бренды и адреса проходят насквозь; текст без кириллицы переводится в кириллицу.

```python
transliterate("Бишкек")                        # 'Bishkek'
transliterate("Bishkek")                       # 'Бишкек'
transliterate("dongolok")                      # 'дөңгөлөк'
transliterate("iPhone 15 Pro Max сатылат")     # 'iPhone 15 Pro Max satylat'
```

### `slugify(text, separator="-", scheme="english", *, normalize=True)`

ASCII-слаг для URL, имён файлов и идентификаторов: только `a-z`, `0-9` и
разделитель.

```python
slugify("Ысык-Көл облусу")             # 'ysyk-kol-oblusu'
slugify("Жалал-Абад", separator="_")   # 'jalal_abad'
slugify("дѳңгѳлѳк Ѳмүр")               # 'dongolok-omur'
```

### `detect_script(text, *, normalize=True)`

`"cyrillic"`, `"latin"`, `"mixed"` или `"unknown"`. Считаются слова, а не
буквы: адреса не учитываются, слово с латинскими двойниками внутри кириллицы
считается кириллическим.

### Прочее

- `normalize_cyrillic(text)` — только [нормализация](#нормализация-ввода), без транслитерации.
- `alphabet_table(scheme)` — список пар `(кириллица, латиница)` для всех 36 букв.
- `Wordlist`, `builtin_wordlist()`, `builtin_names()`, `restore_words()`,
  `ascii_key()` — словари для восстановления `ө`, `ү` и `ң`.
- `get_scheme(name)`, `list_schemes()`, `register_scheme()`, `SCHEMES` — доступ
  к схемам; `UnknownSchemeError` — неизвестное имя. Имена регистронезависимы.
- `Scheme`, `Table`, `apply_table`, `match_case` — собственные схемы и движок.
- `CYRILLIC_LETTERS` — кыргызский алфавит строкой.

## Словарь

Встроенный список — около 510 частотных кыргызских слов (включая районы и
города) и отдельный индекс из 5000 имён и фамилий в `kyrgyz_names.txt`. Как он
работает:

1. слово ищется по «сплющенному» ASCII-ключу — учитываются все варианты набора:
   `ө`/`ү` как `o`/`u` (и `oe`/`ue`), `ң` как `n` или `ng`, `ж` как `j` или
   `zh`, `ы` и `й` как `y` или `i`, `х` как `h`, `kh` или `x`, `ю`/`я` как
   `yu`/`ya` или `iu`/`ia` (паспортная запись);
2. составное слово (через дефис) сначала ищется целиком, потом по частям;
3. если точного совпадения нет — ищется самая длинная основа (минимум 4 символа,
   считая и озвончённую форму: `дөңгөлөк` → `дөңгөлөг`), а к окончанию
   применяется гармония гласных: `dongolokton → дөңгөлөктөн`, `dongologu →
   дөңгөлөгү`. Русские фамильные окончания (`-ов`, `-ев`, `-ова`, `-евич`...)
   не гармонизируются: `Omurov → Өмүров`;
4. для слова с прописной буквы, которого нет ни в словаре, ни среди основ,
   ищется близкое имя по символьным триграммам (`Nurdoolod → Нурдөөлөт`) —
   только если оно однозначно лучшее и отличается по длине не больше чем на
   букву, так что обычные слова не подменяются (`Aytsa → Айтса`, `Bolotov →
   Болотов`);
5. если слово не нашлось, оно разбирается обычными правилами схемы. То есть
   словарь ничего не портит: без него было бы то же самое.

### Спорные слова

Некоторые пары по-английски пишутся одинаково: `uy` — это и «уй», и «үй»,
`kol` — и «кол», и «көл». По умолчанию такой ключ не используется вовсе, и
слово достаётся правилам. Если одно из слов заметно частотнее, его помечают
**предпочтительным** — звёздочкой в файле списка или `preferred=True` в коде:

```text
уй
*үй        # uy -> үй: дом встречается несравнимо чаще коровы
```

```python
words = Wordlist(["уй"]).add(["үй"], preferred=True)
words.lookup("uy")          # 'үй'
words.ambiguous_keys()      # [] — спор решён
```

Во встроенном списке так помечены `үй`, `кол`, `он`, `тоо`, `түз` и `кийин`;
проигравшие пары (`уй`, `көл`, `оң`, `төө`, `туз`) — единственные слова
списка, которые не возвращаются из латиницы. Оставшиеся спорные ключи всегда
видны: `builtin_wordlist().ambiguous_keys()` (сейчас их нет).

### Свой список слов

Одно слово в строке, кириллицей, `#` — комментарий, `*` — предпочтительное
чтение; файл в UTF-8 (BOM Блокнота не мешает):

```python
from kyrgyz_transliteration import Wordlist, builtin_wordlist, to_cyrillic

words = Wordlist.from_file("kyrgyz.txt")               # только свои слова
words = builtin_wordlist().copy().add(["көгүчкөн"])     # встроенные + свои

to_cyrillic("koguchkondon", wordlist=words)   # 'көгүчкөндөн'
```

Чем полнее список, тем лучше результат: встроенный набор — это стартовая точка,
а не полный словарь кыргызского языка и не официальный реестр имён.

Справочник `Wordlist`:

| Что | Зачем |
|---|---|
| `Wordlist(words, min_stem=4)` | собрать словарь из слов (кириллицей); `min_stem` — минимальная длина основы при поиске по началу слова |
| `Wordlist.from_file(path)` / `.from_text(text)` | прочитать список: одно слово в строке, `#` — комментарий, `*` — предпочтительное чтение |
| `.add(words, preferred=False)` | дописать слова; возвращает сам словарь, так что вызовы можно цеплять |
| `.copy()` | независимая копия вместе с предпочтительными словами |
| `.merge(other)` | добавить чужой словарь, не потеряв его пометки |
| `.lookup(typed)` | слово по набранной латинице или `None`, если его нет либо ключ спорный |
| `.lookup_trigram(typed)` | однозначное близкое имя из триграммного индекса или `None` |
| `.lookup_stem(key)` | `(основа, длина ключа основы)` — самая длинная однозначная основа |
| `.ambiguous_keys()`, `.preferred()` | спорные ключи и слова, за которыми они закреплены |
| `.words()`, `len(...)`, `"dongolok" in ...` | содержимое словаря |
| `builtin_wordlist()` | встроенный список слов и имён (кешируется; не меняйте его на месте — делайте `.copy()`) |
| `builtin_names()` | отдельный курируемый список имён и фамилий (кешируется; для изменений делайте `.copy()`) |
| `restore_words(text, wordlist, scheme="english")` | только восстановление слов, без транслитерации |
| `ascii_key(word)` | ключ слова: нижний регистр без диакритики (`dönggölök` → `donggolok`) |

## Свои схемы

Схема — это таблица «кириллица → латиница» плюс необязательные уточнения.
Обратная таблица строится автоматически. Значения — только буквы `A-Za-z`
(или пустая строка), ключи — в нижнем регистре; схема без какой-то из 36 букв
при регистрации отклоняется (`strict=False` отключает проверку).

```python
from kyrgyz_transliteration import SCHEMES, Scheme, register_scheme, to_latin

register_scheme(
    Scheme(
        name="my-docs",
        title="Как в моих документах",
        mapping=dict(SCHEMES["english"].mapping, ж="zh", ң="ng"),
        reverse_word_initial={"e": "э"},
    )
)

to_latin("Жаңыл", "my-docs")   # 'Zhangyl'
```

Полезные поля `Scheme`:

- `word_initial` — замены только в начале слова;
- `reverse_mapping`, `reverse_word_initial` — правки обратной таблицы;
- `latin_upper` / `latin_lower` — регистровые исключения латиницы;
- `forward_contextual` / `reverse_contextual` — контекстные правила
  `(регулярка, маркер)`; правило помечает неоднозначный символ маркером, а
  маркер переводится через `mapping` (прямое направление) или
  `reverse_mapping` (обратное). Замена обязана быть той же длины, что и
  совпадение, поэтому контекст задаётся через `(?<=...)` и `(?=...)`.

[Нормализация ввода](#нормализация-ввода) работает для любой схемы: двойники
букв сводятся к кыргызской кириллице, а уже её переводит ваша таблица.

## Командная строка

```bash
$ kyrgyz-transliteration "Кыргыз Республикасы"
Kyrgyz Respublikasy

$ kyrgyz-transliteration "дөңгөлөк"
dongolok

$ kyrgyz-transliteration "dongolok"
дөңгөлөк

$ kyrgyz-transliteration --no-words "dongolok"     # без словаря, одними правилами
донголок

$ kyrgyz-transliteration -s passport "Айгүл Жумагулова"
Aigul Zhumagulova

$ kyrgyz-transliteration -d cyrillic -s passport "Chui Aitmatov"
Чүй Айтматов

$ kyrgyz-transliteration --slug "Жалал-Абад облусу"
jalal-abad-oblusu

$ kyrgyz-transliteration -i text.txt -o text-latin.txt    # файлы, любая ОС
$ cat text.txt | kyrgyz-transliteration > text-latin.txt  # или так в Unix

$ kyrgyz-transliteration --wordlist kyrgyz.txt "koygoydon"
көйгөйдөн

$ kyrgyz-transliteration --list          # схемы с описаниями
$ kyrgyz-transliteration --table passport    # таблица соответствий
$ kyrgyz-transliteration --detect "Bishkek"
latin
```

Опции:

| Опция | Что делает |
|---|---|
| `-i FILE`, `--input FILE` | читать текст из файла (UTF-8, BOM распознаётся) |
| `-o FILE`, `--output FILE` | писать результат в файл (UTF-8 без BOM) |
| `--encoding ENC` | кодировка входного текста, например `cp1251` для старых файлов Windows |
| `-s`, `--scheme` | схема: `english`, `english_ascii`, `passport`, `bgn_ascii` |
| `-d`, `--direction` | `auto` (по умолчанию), `latin` или `cyrillic`; с явным направлением текст обрабатывается построчно, память не зависит от размера файла |
| `--no-words`, `--wordlist FILE` | выключить встроенный словарь / добавить свой (вместе с `--no-words` — заменить) |
| `--no-normalize` | не чистить кириллицу перед транслитерацией |
| `--slug`, `--detect`, `--list`, `--table [SCHEME]`, `-V` | слаг, определение письменности, список схем, таблица, версия |

Ввод — аргумент `TEXT`, `-i FILE` или стандартный ввод (`-` тоже означает
стандартный ввод). Вывод всегда в UTF-8: кыргызской кириллице нет места ни в
одной однобайтовой кодовой странице Windows (в cp1251 нет `ө`, `ү`, `ң`),
поэтому утилита сама переводит каналы и перенаправления на UTF-8, отбрасывает
BOM и сохраняет переводы строк как есть. В терминале с другой кодировкой
символы, которых в ней нет, печатаются как `\uXXXX`, а не роняют программу.
Явно заданный `PYTHONIOENCODING` уважается. То же самое доступно как
`python -m kyrgyz_transliteration`.

## Как это работает

Один проход по тексту, никаких зависимостей и никакой магии.

1. **Нормализация** (в направлении «кириллица → латиница»): быстрая проверка
   регуляркой, нет ли в тексте подозрительных символов; если есть — NFC,
   замена букв соседних алфавитов и двойников на кыргызские, удаление
   ударений и невидимых символов внутри кириллических слов, починка латинских
   букв внутри кириллических слов. Чистый текст проходит без изменений.
2. **Подготовка таблицы.** Схема хранит таблицу «кириллица → латиница»; обратная
   таблица строится из неё автоматически при первом обращении и кешируется.
   Пустые замены (`ъ`, `ь`) в обратную таблицу не попадают, а при конфликте
   побеждает буква, объявленная раньше.
3. **Словарь** (в направлении «латиница → кириллица») работает до всего
   остального: найденные слова сразу заменяются кириллическими, остальное
   достаётся правилам. Адреса и упоминания вырезаются заранее и возвращаются
   на место нетронутыми.
4. **Контекстные правила.** До основного прохода по тексту проходят регулярки,
   которые помечают неоднозначные символы служебными маркерами: в прямом
   направлении `й` рядом с `ы` → маркер «i», `е` после ъ/ь → маркер «ye»; в
   обратном `y` между гласной и согласной → маркер «й», `t` перед `s` после
   гласной → маркер «т» (или «ц» перед `-ия`, `-есс`), `ee` → «ээ» и так
   далее. Маркер обязан быть той же длины, что и совпадение, — иначе движок
   поднимает `ValueError`, — поэтому контекст задаётся только через `(?<=...)`
   и `(?=...)`, а нумерация символов остаётся прежней.
5. **Жадное сопоставление.** Для каждой позиции берётся самая длинная
   подходящая последовательность (`shch` раньше `sh`, `sh` раньше `s`), в начале
   слова сначала проверяется таблица `word_initial`. Что не нашлось — цифры,
   пунктуация, разметка, чужие алфавиты — копируется как есть.
6. **Регистр.** Он берётся из исходного фрагмента, а не из замены: слово целиком
   в верхнем регистре даёт `ЁЛКА → YOLKA`, с заглавной — `Ёлка → Yolka`,
   многобуквенная замена внутри аббревиатуры смотрит на соседние буквы
   (`ЖЧКнын → JCHKnyn`), одиночная прописная буква в строке КАПСОМ тоже
   печатается прописными (`Ч. АЙТМАТОВ → CH. AYTMATOV`), а у составных слов
   регистр считается по частям: `YSYK-KOL → ЫСЫК-КӨЛ`, `Ysyk-Kol → Ысык-Көл`.

Точки расширения — `Scheme` (своя схема), `Table` + `apply_table` (свой движок
на готовой таблице), `match_case` (восстановление регистра отдельно),
`normalize_cyrillic` (чистка ввода отдельно).

## Рецепты

**Слаг для URL.**

```python
from kyrgyz_transliteration import slugify

slugify("Ысык-Көл облусунун жаңылыктары")   # 'ysyk-kol-oblusunun-janylyktary'
```

**Имя как в паспорте, в том числе для машиночитаемой зоны.**

```python
from kyrgyz_transliteration import to_latin

name = to_latin("Жумагулова Айгүл", "passport")   # 'Zhumagulova Aigul'
mrz = name.upper().replace(" ", "<")              # 'ZHUMAGULOVA<AIGUL'
```

**Поиск, которому всё равно, чем набран запрос.** Приводим запрос к кириллице и
ищем по одному индексу:

```python
from kyrgyz_transliteration import detect_script, transliterate

def normalize(query):
    if detect_script(query) == "latin":
        return transliterate(query, direction="cyrillic")
    return query

normalize("dongolok")    # 'дөңгөлөк'
normalize("Дөңгөлөк")    # 'Дөңгөлөк' — уже кириллица, не трогаем
```

**Файл построчно** — память не растёт, переводы строк сохраняются:

```python
from kyrgyz_transliteration import to_latin

with open("in.txt", encoding="utf-8-sig") as src, open("out.txt", "w", encoding="utf-8") as dst:
    for line in src:
        dst.write(to_latin(line))
```

**Свой словарь из корпуса.** Берём из своих же текстов слова, которые встречаются
хотя бы трижды, — это надёжнее любого готового списка:

```python
import collections
import re

from kyrgyz_transliteration import Wordlist, builtin_wordlist, transliterate

with open("corpus.txt", encoding="utf-8") as handle:
    counts = collections.Counter(re.findall(r"[а-яёңөү-]+", handle.read().lower()))

words = builtin_wordlist().copy()
words.add(word for word, count in counts.items() if count >= 3)
transliterate("dongolokto kochodo", direction="cyrillic", wordlist=words)
# 'дөңгөлөктө көчөдө'
```

## Производительность

Замер на тексте 128 000 символов (Python 3.14, Windows, один поток):

| Операция | Скорость |
|---|---|
| `to_latin`, чистый текст | ~1,7 млн символов/с |
| `to_latin`, текст с двойниками букв (полная нормализация) | ~1,0 млн символов/с |
| `to_cyrillic` без словаря | ~1,5 млн символов/с |
| `to_cyrillic` со словарём (по умолчанию), текст с заглавными словами | ~2 млн символов/с: повторяющиеся слова разбираются один раз |
| сборка встроенного словаря (510 слов) и индекса имён (5000 имён, триграммы) | ~0,1 с, один раз за процесс при первом обратном переводе |

Таблицы схем и встроенный словарь строятся лениво и кешируются, так что первый
вызов `to_cyrillic` дороже остальных; прямое направление словарь не загружает.
Отдельные буквы и короткие строки транслитерировать по одной невыгодно:
накладные расходы на вызов заметнее самой работы — отдавайте движку строку
целиком. На тексте из уникальных слов `wordlist=False` быстрее; если `ө`, `ү` и `ң`
восстанавливать не нужно, отключайте словарь.

## Что не восстанавливается обратно

Обратная транслитерация — не магия. Со словарём круг «кириллица → английская
латиница → кириллица» точен на всём встроенном списке слов (кроме пяти
омографов) и на всех именах (кроме 17 вариантов написания), но неизбежные
потери есть:

- **истинные омографы.** `уй`/`үй`, `кол`/`көл`, `он`/`оң`, `тоо`/`төө`,
  `туз`/`түз` по-английски пишутся одинаково. Одно слово пары выигрывает (см.
  [Спорные слова](#спорные-слова)), другое теряется — без контекста выбрать
  нельзя. То же с именами: `Чынгыз` и `Чыңгыз` — оба `Chyngyz`;
- **слова вне словаря.** `ө`, `ү` и `ң` в них не восстановятся: `koguchkon`
  вернётся как «когучкон», пока «көгүчкөн» не попадёт в список;
- **`е` и `э`:** начальная `e` читается как `э` (кыргызская орфография), долгое
  `ee` — как `ээ`; русские заимствования с начальной «е» (евро, Европа,
  Евразия, ЕАЭБ) восстанавливаются только потому, что есть в словаре;
- **`ъ` и `ь`** в латинице видны только перед `е` (`podyezd`, `Vasilyevich`);
  `semya`, `Ilyas` вернутся как «семя», «Иляс»;
- **`yo`/`yu`** после `o`/`u` — это `ё`/`ю` (боёк, коён), после `a`/`e`/`i`/`u`
  `yo` — это `й + о` (район); `й + ө`/`й + ү` (күйөө, түйүн) различимы только
  по словарю;
- **`ң` и `н + г`** в схеме `bgn_ascii` совпадают (`Narynga`), в остальных
  схемах `ң` и `н` совпадают.

Если нужны точные исходные буквы `ө`, `ү` и `ң`, передавайте кириллицу или
используйте собственную схему с их ASCII-кодированием (например `oe`, `ue`,
`ng`), не добавляя диакритики.

## Совместимость

- Python 3.9+, стандартная библиотека, ни одной внешней зависимости.
- Типы аннотированы, пакет помечен `py.typed` — mypy и IDE видят подписи.
- Работает с любым текстом: цифры, пунктуация, разметка, переводы строк и чужие
  алфавиты проходят насквозь. Исключение — кириллические слова: их
  [нормализация](#нормализация-ввода) убирает ударения, невидимые символы и
  двойники букв (отключается `normalize=False`).
- Специальных блокировок для потоков нет, но и общего изменяемого состояния тоже:
  таблицы схем и встроенный словарь строятся лениво и публикуются только
  целиком, так что худшее, что может случиться в гонке, — двойная сборка
  одного и того же кеша. Исключение — `register_scheme()` и `Wordlist.add()`:
  их вызывайте при старте приложения, а не из рабочих потоков.

`python -X utf8 ...` (или задайте `PYTHONUTF8=1`), иначе вывод кириллицы в
самих тестах может падать; у утилиты `kyrgyz-transliteration` этой проблемы
нет.

Примеры из docstring'ов тоже тесты: `testpaths` включает `src`, а `addopts` —
`--doctest-modules`, поэтому код в документации не может разойтись с поведением.

Нашли слово, которое разбирается неверно, — тест пишется в одну строку:

```python
@pytest.mark.parametrize("word", ["көпөлөк", "сүйлөшүү"])
def test_my_words_round_trip(word):
    assert to_cyrillic(to_latin(word)) == word
```

В PyCharm: Settings → Project → Python Interpreter → Add → Existing →
`.venv/bin/python` (Windows: `.venv\Scripts\python.exe`). Пакет установлен в
editable-режиме, поэтому `import kyrgyz_transliteration` работает без правки
`sys.path`, а тесты запускаются правым щёлчком по `tests/`.

## Как помочь

- **Пополнить словарь.** Частотные кыргызские слова с `ө`, `ү`, `ң` —
  `src/kyrgyz_transliteration/data/kyrgyz_frequent.txt`, одно слово в строке.
  Файлы правятся как обычный текст; в собранный пакет они попадают сжатыми
  автоматически (`hatch_build.py`).
  Слова без этих букв тоже полезны: они подтверждают, что этих букв в слове нет,
  и гасят ложные срабатывания по основе. Проверьте, что новое слово не создаёт
  спорный ключ: `builtin_wordlist().ambiguous_keys()` (тест
  `test_corpora.py` следит за этим); если создаёт — пометьте более частотное
  слово звёздочкой.
- **Уточнить паспортную таблицу.** Схема `passport` построена по таблице ICAO
  Doc 9303 и наблюдаемой практике ГРС; если у вас есть приложение к Инструкции
  (постановление № 238 от 21.04.2017 с изменениями), сверьте строки `ө`, `ү`,
  `ң`.
- **Добавить схему.** Достаточно таблицы букв — см. [Свои схемы](#свои-схемы).
  В `tests/test_schemes.py` схема автоматически проверяется на полноту алфавита.
- **Прислать слово, которое разбирается неверно.** Это самое ценное: пример
  «набрал X, ожидал Y, получил Z» превращается в тест и правило.
